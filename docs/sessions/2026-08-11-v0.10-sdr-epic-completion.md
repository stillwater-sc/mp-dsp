## What shipped

### 1. SDR link demonstrator — #104 (`ab0f99d`, merged `1f80620`)

`applications/sdr_demo/` — a full TX → AWGN → RX link swept over 15
number-system configurations × 4 modulations (QPSK through 256-QAM), across
IEEE, cfloat, posit and fixpnt at 8/12/16/32 bits. Five CSVs: sweep, Pareto,
constellation clouds, per-block attribution, input backoff.

The design decision that matters: where `analysis/sdr_precision` (#103)
projects coefficients into the narrow type and computes in `double`, this
instantiates `PolyphaseInterpolator<Coeff,State,Sample>` and
`FIRFilter<Coeff,State,Sample>` on the type under test, so the *arithmetic*
runs narrow. Both views are reported and labelled — they answer different
questions and the difference turned out to matter (see §5).

The reported metric is **implementation loss**,
`10*log10(EVM_narrow² / EVM_double²)` at the Eb/N0 that puts the double chain
at BER 1e-3, with 1 dB the usability threshold. The reference is re-measured
at the sweep's own symbol count and seed so the narrow chain sees the same
noise realization and most sampling variance cancels in the ratio.

**The issue's acceptance criterion "demonstrates that posit achieves higher
modulation order at same bit-width" could not be met, because it is false.**
At 8 bits on 16-QAM, `fixpnt<8,5>` cost 0.81 dB (usable) against 1.27 dB for
both `posit<8,2>` and `cfloat<8,4>` (not usable). Rather than tune parameters
until the claim came true, the demo adds the measurement that isolates where
the tapered format *does* win — an input-backoff sweep that attenuates signal
and noise together so Eb/N0 is unchanged. There `fixpnt<8,5>` is best at full
scale and completely lost by −36 dB while `posit<8,2>` holds. That conclusion
is derived from the sweep data at run time rather than printed from a stored
string, so changing the parameters changes the finding.

### 4. `FractionalDelay` default — #208 (`421f197`, merged `8a54b4c`)

`multirate::FractionalDelay`'s default `taps_per_phase = 12` was rejected by
its own validator, so construction with the documented defaults always threw.
The doc comment recommended 12, 16 and 24 — all even, all throwing.

The issue offered two fixes; the measurement chose. Odd `K` keeps the group
delay `(K-1)/2` an integer, which makes phase 0 `sinc(k − center)` sampled on
the integers — one non-zero tap, an unfiltered passthrough, measured at 3e-17.
With even `K` the floor is a half-integer and *no* request lands on an
unfiltered tap. So the constraint stayed and the default moved to 11.

Two things beyond the report: validation moved from the constructor body into
`design_bank` (the body runs after the whole initializer list, so a check there
could not fire first), and the class turned out to have **no unit test at all**
— the issue said it had tests, but those cover `instrument::FractionalDelay`, a
different class. That absence is exactly why the default could sit broken.

Files: `include/sw/dsp/multirate/fractional_delay.hpp`,
`tests/test_multirate_fractional_delay.cpp` (new, 360 lines),
`tests/CMakeLists.txt`, `CLAUDE.md`, `docs-site/.../fractional-delay.md`

### 5. The 8-bit study — #209 (`aeb7b0d`, merged `50cba61`)

`sdr_demo --study`: the whole 8-bit design space (`fixpnt<8,4..7>`,
`posit<8,0..2>`, `cfloat<8,2..4>`), a three-scalar factorial over all eight
narrow/double corners, and loss-vs-Eb/N0 curves across 18 dB.

**#104's 8-bit headline did not survive**, on two independent counts:

- `posit<8,1>` (0.36 dB) and `cfloat<8,3>` (0.48 dB) both beat `fixpnt<8,5>`
  (0.81 dB) and neither was in the original sweep. Within-family spread —
  fixpnt 3.35 dB, posit 1.10 dB, cfloat 0.80 dB — dwarfs the 0.46 dB
  between-family gap the conclusion rested on.
- Most of what the two losing formats lose is a **systematic gain error**, not
  precision. Both fit a cloud gain of 0.935; fitting it out, as a receiver's
  AGC does for free, drops them to ~0.58 dB, inside the budget.

Two further findings:

- `posit<8,2>` and `cfloat<8,4>` agreed to three digits because both leave 3
  mantissa bits at unity amplitude. A coincidence of parameterization, not the
  shared bottleneck it looked like — confirmed by a second exact agreement
  between `cfloat<8,2>` and `fixpnt<8,5>`.
- `fixpnt<8,7>` reports a **negative** implementation loss, which no precision
  effect can produce. Its range is ±0.992 against a waveform peaking near 0.97,
  so the datapath saturates — a compressive nonlinearity that clips the noise
  tail (lowering EVM) while pulling symbols toward the decision boundary
  (raising BER). Such rows are now flagged `LIMITING` and excluded from ranking.

Files: `applications/sdr_demo/sdr_demo.cpp`,
`docs-site/src/content/docs/sdr/precision.md`

## Design decisions worth remembering

- **Datapath blocks and feedback loops fail in opposite ways, so the design
  response is opposite.** Datapath separates the number systems across orders
  of magnitude (channelizer reconstruction 1.5e-16 → 3.1e-04; OFDM ICI −309 dB
  → −68 dB), and `posit<32,2>` beats `float` by 14–22 dB at equal width. The
  synchronization loops do not separate them *at all* — timing jitter is
  2.361e-01 for `double`, `float`, `posit<32,2>`, `cfloat<32,8>` and
  `posit<16,2>` alike. A loop is precision-insensitive until it crosses a ULP
  threshold and stops dead, so the fix is changing what the state holds
  (relative position, wrapped phase, deviation from nominal), never widening
  the type.
- **Spend width on the accumulator first.** The three-scalar factorial puts
  essentially the whole 8-bit loss in `StateScalar` — 1.28 dB of 1.28 dB for
  `posit<8,2>` — against 0.05 dB for coefficients and 0.19 dB for the sample
  stream.
- **A negative implementation loss is a broken metric, not a good result.**
  Anything that reports better-than-`double` is limiting, and EVM has stopped
  being a valid proxy. `ChainResult` now carries fitted gain and residual EVM
  so this is visible rather than hidden.
- **Attribution and cost are different questions.** `analyze_blocks` projects
  coefficients and computes in `double`, so it measures storage sensitivity and
  named the constellation table the largest 8-bit contributor. Real narrow
  arithmetic puts the cost in the accumulator instead. Neither tool is wrong;
  design decisions need the second.
- **Measure the delay, don't correlate a tone.** The first `FractionalDelay`
  accuracy test correlated a delayed sinusoid and reported 20.0 samples of
  error — a sinusoid's autocorrelation is periodic and the peak search locked
  onto the wrong lobe. Broadband noise fixed the ambiguity but left 7e-02 of
  bias. The first moment of the impulse response *is* `−dφ/dω` at DC rather
  than an estimate of it: 6e-04.
